## 9a: `moderation/queries.py` and the export commands
- `get_conversation_bundle(conversation_id, *, include_identities=False) -> dict`: one JSON-serializable nested dict: `conversation` (id, status, source, experiment name/kind, pair_id, variant, label_seed, created_at, ended_by label or null), `topic` (id, proposition, title, leans), `participants` (label, join_order, joined_at, `pseudonym`: a stable id such as `p-<8 hex>` derived from a keyed hash of the user pk with the project's secret, never the pk itself; null user for synthetic), `messages` (seq_no, author_type, participant label, in_reply_to seq, content, char_count, planted, created_at), and `runs` (all runs, live and replay, oldest first: id, kind, replicate, replay_of, status, failure_reason, attempts, is_stale, decision, rationale, trigger seq, snapshot_seq, posted message seq, config_snapshot, discussion_map, timings, error) each with `issues` (all fields incl. quote offsets, quote_match, validity, rejection_reason, disposition and reason), `acts` (all fields incl. features, validity, rejection_reason, source issue local_ids and source message seqs), and `llm_calls` (agent, attempt, model, prompt_version, prompt_sha256, tokens, cache tokens, cost_usd, reserved_usd, latency_ms, status, error_code, and `request`/`raw_response`/`parsed` **only when** the caller passes `include_raw=True`). Everything refers to messages by `seq_no`, never by pk. Totals: `cost_usd` per run and for the conversation.
- **Privacy:** with `include_identities=False` no username, email, user pk or display name appears anywhere in the output, including inside `request`/`raw_response` text (the prompts contain none by construction; the test scans the serialized output for the seeded users' names and emails). With `include_identities=True`, each participant additionally has `username` and `email`.
- `list_conversations(*, source=None, status=None, experiment=None, topic_id=None, has_runs=None, since=None, until=None, limit=None) -> list[dict]` (id, topic proposition, source, status, experiment, pair_id, variant, counts of user messages, moderator messages and runs by status, total cost, created_at), newest first; filters combine with AND; unknown filter values raise ValueError.
- `export_conversation(conversation_id, *, include_identities=False, include_raw=False) -> str`: `json.dumps(bundle, indent=2, sort_keys=True, ensure_ascii=False)` plus a trailing newline. Deterministic: two calls give identical text.
- `manage.py export_conversation <id> [--include-identities] [--include-raw] [--output PATH]` (default stdout); `manage.py export_all [--include-identities] [--include-raw] [--source ...] [--status ...] [--experiment ...] --output-dir DIR` writes one `conversation_<id>.json` per conversation plus `index.json` (the `list_conversations` result) and refuses to overwrite existing files unless `--force`. A missing conversation id gives a clear error and non-zero exit. The commands never read `.env`.
- Round trip test: build a rich conversation (users, messages, several runs live and replay, issues with dispositions, acts with sources, LLMCall rows) with a helper, export it, parse the JSON, and compare every stored field to the database.
- Queries must not be N+1 (use `select_related`/`prefetch_related`; a test asserts a query-count ceiling that does not grow with the number of messages).

## 9b: `analysis/metrics.py` (pure functions on pandas frames; no Django, no DB)
Frames are plain `pandas.DataFrame`s with the columns below; the builders from the database come in steps 14/16, so this step is tested on hand-built fixtures.
- `findings` frame (one row per consensus finding = ground truth): `finding_id, conversation_id, message_id, side ("left"|"right"), dimension, intensity (0-4), difficulty ("obvious"|"hard"|None), pair_id`.
- `matches` frame (Master issues matched to findings): `finding_id, issue_id, issue_valid (bool), acted (bool: the issue's disposition is `acted` AND an act from it was posted)`.
- `issues` frame (all Master issues, for false positives): `issue_id, conversation_id, message_id, side, dimension, intensity (nullable), validity ("valid"|"rejected"), rejection_reason, matched (bool: linked to a finding with intensity >= `error_threshold`)`.
- `runs` frame (data quality): `run_id, conversation_id, side, status, failure_reason`.
- Functions, each returning a DataFrame (long form, stable column order, deterministic row order), with `n` (denominator) always included and rates as floats or NaN when `n == 0` (never divide by zero, never invent a 0):
  - `detection(findings, matches, *, by=("dimension","side","intensity"))`: D = P(Master raises a valid matching issue | a finding at that intensity), columns `by + [n_findings, n_detected, rate]`.
  - `action(findings, matches, *, by=...)`: A = P(Intervenor acts | the issue was raised), restricted to detected findings: `n_detected, n_acted, rate`.
  - `false_positives(issues, *, by=("dimension","side"), error_threshold=INTENSITY_ERROR_THRESHOLD)`: share of valid Master issues whose finding is below the threshold or absent (`matched == False`): `n_valid_issues, n_false, rate`. (The plan phrases it as the share of phrases rated 0 or never flagged that were flagged; with the data available this step, the frame holds issues, so the rate is per issue and the docstring says so.)
  - `data_quality(issues, runs, findings, *, by=("side",))`: rejected-issue rate (by reason too), failed and skipped run rates (by status and `failure_reason`), and the not-scorable rate if a `not_scorable` boolean column is present in `findings` (optional column).
  - `side_gap(table, *, value="rate", sides=("left","right"), keep=(...))`: for a table above, the right-minus-left difference of the rate at each equal-intensity (equal difficulty) cell where BOTH sides have `n >= min_n` (default 1); cells where one side is empty are reported with `comparable=False` and NaN gap, never dropped silently. Also returns `overlap` info: which intensity values both sides share.
  - `gap_decomposition(findings, matches, *, by=("dimension","intensity"))`: for P(acted | finding) = D x A, the right-minus-left gap split into a detection component and an action component using the average of the two orderings (Shapley/symmetric decomposition): `gap_total = gap_D*mean(A) + mean(D)*gap_A` per cell, columns `gap_total, detection_component, action_component`, and the components sum to the total to within 1e-12 wherever all four rates are defined. (Proposal for the pre-registration, step 16; documented in the docstring.)
- Inputs are validated: missing columns raise `ValueError` naming them; unknown `side`/`dimension` values are kept as they are (no silent filtering) but `side` outside left/right raises for `side_gap`. Input frames are never mutated.
- Known-answer tests: a hand-built fixture of about 40 rows with the expected tables written out by hand in the test (not computed with the same code).

## Amendment (architect, 2026-09-26): 9a bundle shape as built (pinned)
- Top level keys: `conversation`, `topic`, `participants`, `messages`, `runs`, `unattached_llm_calls`, `cost_usd`. `conversation.experiment` is `{"name","kind"}` or null; `list_conversations` rows and the `experiment` filter use the bare name. `conversation.transcript_id` is included. `conversation.ended_by` is a label or null.
- `cost_usd` is a float, at the top level of the bundle and per run. The conversation total counts every ledger row that names the conversation or belongs to one of its runs (rows naming only the conversation are listed in `unattached_llm_calls`). A null call cost counts as 0.
- Issues carry flat `disposition` and `disposition_reason` (null when none) and are identified by `local_id` and their message's `seq_no`; acts carry `features` as a nested dict and `source_issues` (local_ids) and `source_messages` (seqs), sorted. No pk of a participant, message, issue or user appears; `created_by` is not exported.
- Pseudonym: `p-<8 hex>` = HMAC-SHA256 keyed with `settings.SECRET_KEY` over `export-pseudonym:<user pk>`. Stable across conversations.
- `get_conversation_bundle(..., include_raw=False)` and `export_conversation(..., include_raw=False)` both take `include_raw`. A missing conversation raises `Conversation.DoesNotExist` (the commands turn it into a `CommandError`, non-zero exit). `list_conversations` raises `ValueError` for unknown source/status/experiment/topic id, a non-bool `has_runs`, a bad date or a bad `limit`; `since` and `until` are inclusive, naive values count as UTC. `runs` in a listing row is a sparse dict of counts by status (missing keys read 0).
- `export_conversation --output` creates parent directories and overwrites; `export_all` aborts before writing anything if any target exists, unless `--force`; `index.json` never contains identities.
- Message text is exported as stored; it is not scrubbed for usernames a participant may have typed. Constant query count (9 for the bundle, with or without identities).

## Amendment (architect, 2026-09-26): 9b as built (pinned)
- Each function requires only the columns it uses (missing ones raise `ValueError` naming them). Duplicate `finding_id` in `findings` raises `ValueError`; `matches` rows for an unknown `finding_id` are ignored. A finding is *detected* if any of its `matches` rows has `issue_valid`; *acted* only if a valid row also has `acted`. The boolean columns must hold no nulls.
- `false_positives(issues, *, by=("dimension","side"))`: **the `error_threshold` parameter is removed.** The `matched` column of the `issues` frame is prebuilt by whoever builds the frame (steps 14/16), applying `INTENSITY_ERROR_THRESHOLD` there; the function only counts. Cells come from all issues, so a cell with only rejected issues shows `n_valid_issues = 0` and a NaN rate.
- `data_quality(issues, runs, findings=None, *, by=("side",))` is long form: `by + [measure, category, n, count, rate]`, measures `issue_rejected`, `run_status`, `run_failure_reason`, `not_scorable` (the last only when `findings` has that column). Zero-count rows for absent reasons/statuses stay (explicit 0). An empty rejection reason is labelled "(none)".
- `side_gap` and `gap_decomposition` as the builder documented: `comparable` is true only when both sides are present with `n >= min_n` and defined values; the overlap of comparable intensity values is in `result.attrs["overlap"]` and via the public helper `intensity_overlap(result)`; decomposition components are NaN when either side has no detected finding.
- All outputs sorted by the key columns (missing keys last), fixed column order, counts int64, rates float64 (NaN when `n == 0`); an empty input gives an empty frame with the right columns.
- Key names as built are pinned: an issue's message is keyed `message` (its `seq_no`); runs carry `trigger_seq` and `posted_seq`; act sources are `source_issues` (local_ids) and `source_messages` (seqs); a synthetic participant exported with identities has present keys `username` and `email` set to null; `index.json` uses the same JSON format as the export files; timestamps are ISO 8601 text.
