## Interface (fixed)
`moderation/worker.py`:
- `claim_next_run(*, now=None) -> ModerationRun | None`: atomically claims the oldest claimable run and returns it, or None. **Claimable** = `kind == "live"`, `status == "pending"`, and no other run of the same conversation is currently `running` (this serializes runs per conversation even with several workers). "Oldest" = `created_at`, then `id`. The claim is one atomic conditional UPDATE (`status` pending -> running, `claimed_at = now`), so two workers can never claim the same run (the loser sees zero rows updated and tries the next candidate). The claim does NOT increment `attempts` and does not set `started_at`: `run_moderation` does both (docs/step5_brief.md, 5b). **Replay runs (`kind="replay"`) are never claimed by the worker**: they are created and executed by the step 13 replay command under its own spending cap.
- `reap_stuck_runs(*, now=None) -> dict`: runs `running` whose `claimed_at` is older than `RUN_TIMEOUT_SECONDS` (live runs only) go back to `pending` if `attempts < RUN_MAX_ATTEMPTS`, otherwise to `failed` with `failure_reason="timeout"` and `finished_at` set. Returns `{"requeued": n, "failed": m}`. Never touches `done`, `failed`, `skipped_*` or `pending` runs. Idempotent. A requeued run keeps `attempts`, and a later `run_moderation` retry clears the earlier attempt's rows (already implemented in 5b).
- `process_one(*, now=None) -> ModerationRun | None`: claim one run, call `moderation.pipeline.run_moderation(run)`, return the refreshed run, or None if nothing was claimable. **A crash inside a run** (any exception from `run_moderation`, including the programming-error re-raise) is caught, logged with `logger.exception` (message without user text), the run is left `failed` (if `run_moderation` did not already do so, set `status="failed"`, `failure_reason="internal_error"`, `finished_at`), and `process_one` returns normally so the worker continues. It does not catch `KeyboardInterrupt`/`SystemExit`.
- `run_worker(*, once=False, max_runs=None, poll_seconds=None, stop=None, sleep=time.sleep) -> int`: runs the reaper once at start and then every `RUN_TIMEOUT_SECONDS / 2` seconds (or at least every 30 s), then loops `process_one` until nothing is claimable, then sleeps `poll_seconds` (default `WORKER_POLL_SECONDS`) and repeats. `once=True`: reaper, then process every claimable run, then return. `max_runs`: stop after that many processed runs. `stop`: an optional callable or `threading.Event`; the loop exits when it is set/true. Returns the number of runs processed. The loop must survive a database error on a single iteration (log, sleep, continue) and must never busy-loop.
- Signals: SIGINT/SIGTERM finish the current run and exit cleanly (the management command wires this; `run_worker` itself stays testable through `stop`).

`manage.py run_moderator`: options `--once`, `--max-runs N`, `--poll-seconds S` (float, default the tunable). Prints one line at start (worker started, mode, poll interval) and one line per processed run (run id, conversation id, final status, failure_reason if any). Refuses to start with a clear message and non-zero exit if `MODERATION_RUN_MODE == "sync"` (sync mode runs inline; a worker would be redundant and confusing). It never reads `.env` itself (settings do) and never prints keys or user text.

`scripts/dev.sh` (bash, `set -euo pipefail`): starts `manage.py runserver` and `manage.py run_moderator` with the project's `.venv/bin/python`, in the background, prefixes each line of output with `[web]` / `[worker]`, and on Ctrl-C or when either process exits stops the other and exits. It must not source or print `.env`. Executable bit set. It prints one reminder line: "LLM_ENABLED is False in config/tunables.py: moderation runs will be recorded as skipped_disabled until it is turned on."

## Details and rulings
- Ordering across conversations is global oldest-first; the per-conversation serialization is the "no other running run in the same conversation" rule above.
- A run already `running` with an old `claimed_at` is the reaper's business; `claim_next_run` never takes over a `running` run.
- Time is taken from `django.utils.timezone.now()` (or the `now` argument) so tests can control it.
- New tunables only if genuinely needed (for example a reaper interval); every number lives in `config/tunables.py` with a comment on the line before it.
- Do not edit `moderation/pipeline.py`, `forum/*`, or any existing test. If the pipeline needs a change, report it to the architect.

## Tests (tester, `tests/worker/`, FakeLLM only; write them from this contract before/without reading `worker.py`)
Oldest first (created_at, then id); replay runs and non-pending runs are never claimed; two claimers never get the same run (a real thread/race test on a file database, repeated) and each pending run is claimed exactly once across N workers; per-conversation serialization (a conversation with a running run is skipped, others proceed); the claim leaves `attempts` and `started_at` alone; reaper: exact boundary at `RUN_TIMEOUT_SECONDS`, requeue below `RUN_MAX_ATTEMPTS`, fail at it with reason `timeout`, ignores non-running and replay runs, idempotent, returns counts; a crash in `run_moderation` (monkeypatched to raise) marks the run failed, is logged without leaking text, and the next run is still processed; `process_one` returns None on an empty queue; `run_worker` with `once`, `max_runs`, `stop`, sleeps between empty polls (fake `sleep`), never busy-loops, survives a database error on one iteration, reaper runs at start; end to end with FakeLLM: post a message through `forum.services.post_message` in worker mode, run the worker once, and the moderator message exists and the run is `done` (and with `LLM_ENABLED` False the run ends `skipped_disabled` and nothing is posted); the management command (`call_command`) options, refusal in sync mode, output lines contain no username/email/message text; `scripts/dev.sh`: exists, executable, `bash -n` passes, contains no reference to `.env`, starts both commands (static checks; do not run the servers). Then an independent mutation pass on a true `rsync -a` copy outside the repo (claim not atomic, ordering reversed, replay claimed, attempts incremented in the claim, reaper boundary off by one, crash not caught, sleep removed, sync-mode refusal removed, ...).
