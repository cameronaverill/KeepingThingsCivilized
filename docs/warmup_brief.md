# Warm-up transcripts brief (non-political test set for the bias pipeline)

Status: contract for the agents, written 2026-09-26. Plan reference: section 9, "Non-political warm-up" (test family 3). The warm-up uses the same paired and mechanical machinery as the golden set, but on low-stakes topics where matched pairs are easy to write and planted errors are plainly false. It shakes out the code, the metrics and the analysis before any sensitive content, and gives a baseline for pro/con treatment without a partisan question. **Its results validate the pipeline; they are not evidence of political neutrality.** The owner will scrutinise these scenarios in plan step 17, so write them to be audited, not just to pass checks.

## What to write
Read first: `docs/neutrality.md`, `docs/step3_brief.md` (transcript format, pair design rules, mechanical series), `docs/step3_review_pack.md`, `scripts/make_review_pack.py`, `moderation/management/commands/spike.py` (`validate_transcript`, `_validate_series`, `_check_against_base`, `planted_spans`), `moderation/series.py`, and several existing files under `golden/transcripts/` (a paired factual one, an abusive one, an obvious factual one, and one of each series kind) so the new files follow exactly the same JSON shape and conventions (ids, `pair_id`, `variant`, `description`, `topic`, `messages` with `seq`, `author`, `text`, `planted`, trigger, the `computed` block for series, the message length and count limits).

Three topics, each with a low-stakes proposition a person can agree or disagree with: **school start times**, **bike lanes**, **remote work** (use these as the topic titles; use exactly the proposition strings in `forum/seed_topics.json` so the topics agree with the seeded ones, read them from there). For each topic write two matched pairs: an **obvious factual** pair (a plainly false, generally known claim planted at intensity 3 or 4) and an **abusive-phrase** pair (a direct insult planted at intensity 3 or 4). That is 6 pairs = 12 transcripts. Then a **mechanical series** on ONE of the topics (bike lanes) following the golden set's series conventions exactly (message length ladder, label swap, flooding, repetition, unanswered question), each for both variants, with the base transcript in the same folder so the series base check passes. Aim for about 22 files in total. Do not write "hard" factual pairs and do not write singles.

**Variants.** The paired machinery labels the two variants `left` and `right` (political direction). Low-stakes topics have no political direction. Read how the golden files and the validators use `variant`; keep the same two variant names so the existing tools work, define in `docs/warmup_notes.md` what they mean for this set (which side of the proposition each variant argues: the position stated by the proposition versus the opposing one), and state plainly that they are NOT political codings. Each pair must be identical in structure, length (within about 5%), clarity, logic, hedging, number of checkable assertions and procedural conduct; only the position argued differs, with the same planted problem at the same intensity in the same place. The planted problem sits in the same message number in both variants. Text is realistic, civil, plain English, written the way two thoughtful strangers would write, with sources named only if real and safe (avoid claims a reader could mistake for facts about real people). No real personal names, no slurs beyond what the abusive pair needs (use direct insults such as "idiot" or "clueless fool", not slurs or profanity), no political content, no mention of the study.

`docs/warmup_notes.md` (yours): one paragraph per pair saying what is planted where and at what intensity, what "matched" means for it, the variant definitions, and a candid list of known weaknesses of the set.

## Checker's tests (`tests/warmup_set/`)
Every file validates with the spike's own `validate_transcript` (and series validation) with the folder as the known set; JSON shape identical to the golden files' (same keys, types); unique ids, `pair_id` groups of exactly two with variants `left` and `right`; each pair matched: message counts equal, every corresponding message within 5% length, planted spans present in the same message number with equal intensity and dimension, checkable-assertion counts equal (use the computed fields the golden files carry if they have one, otherwise a documented count of sentences with digits or named facts, agreed by inspection); the topic titles and propositions equal `forum/seed_topics.json`'s; no message longer than `MAX_MESSAGE_CHARS`, at most `MAX_USER_MESSAGES_PER_CONVERSATION` user messages; series factor values in the `computed` blocks equal `moderation.series.compute_features` on the transcript (never hand-labelled); no email address, URL or personal name; no participant label spelled inside message text; the warm-up loads with the replay machinery (`moderation.replay.load_experiment` on the folder, both assignments, then `dry_run_plan`: expected conversation and run counts) using only the fake LLM and no database file other than the test database; the golden folder is untouched (compare a hash of `golden/transcripts/` before and after in the test). Then a short mutation pass: corrupt copies of the files (length mismatch, planted span moved, wrong pair size, wrong computed value, added URL) and prove each is caught.
