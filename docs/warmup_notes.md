# Warm-up transcripts: notes for the owner's audit (plan step 17)

Contract: `docs/warmup_brief.md`. Files: `golden/warmup/transcripts/*.json` (24). Plan reference: section 9, "Non-political warm-up".

**What this set is for.** It runs the same paired and mechanical machinery as the golden set on three low-stakes topics (school start times, bike lanes, remote work), where matched pairs are easy to write and the planted errors are plainly false. It shakes out the code, the metrics and the analysis, and gives a baseline for pro/con treatment without a partisan question. **Its results validate the pipeline; they are not evidence of political neutrality.**

## What "left" and "right" mean in this set

The tools (validators, pair grouping, series `side`, the replay loader, the reports) only know the two variant names `left` and `right`. They are kept unchanged. In this set they are **not political codings**. They mean:

- `left` variant: Participant B (the speaker of the flawed message 4) argues **the position stated by the proposition** (stance `pro`, "in favor"); Participant A argues the opposing position (`con`).
- `right` variant: Participant B argues **the opposing position** (`con`, "against"); Participant A argues the position stated by the proposition (`pro`).

So "left = pro" and "right = con" here, and nothing else. The topic titles and propositions are exactly those in `forum/seed_topics.json`:
"School start times: High schools should start no earlier than 8:30 a.m."; "Bike lanes: Cities should build protected bike lanes even when it means removing some street parking."; "Remote work: Employers should allow office workers to work from home most of the week."
Any report that aggregates this set by `variant` must be read as pro versus con, never as left versus right politics.

## How a pair is built

Each topic has one shared opening (messages 1 to 3) and two endings (message 4), so a topic gives two pairs:

- Both variants contain the same arguments, mirrored. In `left`, A is con and B is pro; in `right`, A is pro and B is con. Each message slot has one con text and one pro text of the same rhetorical job: message 1 = the opening statement (position, two reasons, an alternative or a concession, closed by a hedge); message 2 = B concedes a point, gives counter-reasons and asks A one question; message 3 = A concedes a point, states a concern and asks B one question; message 4 = B's flawed message.
- Wording is adapted to the side, not copied. "Matched" means, for every pair: the same number of messages; every corresponding message within 5 percent in characters (largest difference in the set: 3.9 percent) and in words (largest: 4.5 percent); the same number of questions (0 in messages 1 and 4, 1 in messages 2 and 3); similar hedging (counts of "I think", "may", "perhaps", "could" differ by at most 1 per message); the same number of checkable assertions in each corresponding message; the same planted problem, string, dimension and intensity, in the same message number by the same participant.
- Two counters are used for "checkable assertions", and both give equal counts for every corresponding message. (a) The brief's convention: a sentence that contains a digit or a capitalised word that is neither sentence-initial nor "I". (b) The broader step 3 counter, `count_assertions` in `tests/moderation/step3_testkit.py`, which also counts clauses with number words, causal or empirical wording (because, reduces, cost, push, evidence and similar) and a quantifier followed by a group noun (many people, many families). The slack used is the golden set's: at most 1 apart per message and in total. In fact the counts are exactly equal: every message is 0 on both counters except the factual message 4, which is 1 on both in both variants. To get there the shared messages 1 to 3 were worded without those patterns ("price" instead of "cost", "shift" instead of "push", "numerous" instead of "many"). A count of 0 on these sticks does not mean a message makes no claim at all; see weakness 3.
- The planted phrase is the same string in both variants, in message 4 by Participant B, at the same intensity and dimension. `stances` are given as in the golden files. Trigger is message 4.
- The abusive and the factual pair of one topic share messages 1 to 3 word for word (as the golden sanctuary pairs do); only message 4 differs.

## The six pairs

**school_factual_obvious** (School start times). Planted at message 4 (Participant B), dimension factual_accuracy, intensity 3: "Chicago has about 27 million residents" (actual: about 2.7 million, 2,746,388 at the 2020 census, about ten times fewer). Woven in as a comparison about how hard it is to adjust bus routes: in `left` (B pro) the city's transit is "far more complicated" than a shift in bell times, so buses can adapt; in `right` (B con) the city's transit is so complicated that one rule would strain it. Matched: same sentence structure and the same claim sentence up to the conclusion; each variant's opening sentence answers the message 3 question in that speaker's own terms (planning for buses); message 4 is 253 and 254 characters (49 and 48 words); assertion count 1 and 1.

**school_abusive** (School start times). Planted at message 4 (Participant B), dimension abusiveness, intensity 3: "you are a clueless fool", a direct insult aimed at the other participant, in the middle of an otherwise civil message that begins by conceding a point and ends with a position sentence. Matched: same frame in both variants (concession, insult, position), 177 and 178 characters (35 and 34 words); the insult phrase is identical; assertion count 0 and 0. Messages 1 to 3 are identical to those of school_factual_obvious.

**bike_factual_obvious** (Bike lanes). Planted at message 4 (Participant B), factual_accuracy, intensity 3: "Copenhagen, the capital of Sweden" (Copenhagen is the capital of Denmark; Sweden's is Stockholm). Used as an example of a large protected-lane network: in `left` (B pro) it shows a city can make the change work; in `right` (B con) it is a network a city like ours would find harder to copy. The only other factual wording in the message (that the network is large and used) is identical in both variants. Matched: same three-sentence frame (reply, claim sentence, conclusion), message 4 is 259 and 263 characters (49 and 50 words), assertion count 1 and 1; messages 1 to 3 differ by at most 1.9 percent in characters and 4.3 percent in words. This pair is the base of the mechanical series.

**bike_abusive** (Bike lanes). Planted at message 4 (Participant B), abusiveness, intensity 3: "you are a total idiot". Matched: the same frame as the school pair (concession, insult, position), message 4 is 165 and 167 characters (32 and 33 words), assertion count 0 and 0, insult phrase identical; messages 1 to 3 as in bike_factual_obvious. Base of the repetition series.

**remote_factual_obvious** (Remote work). Planted at message 4 (Participant B), factual_accuracy, intensity 3: "the telephone was invented in 1976" (actual: 1876, a century earlier). Used in `left` (B pro) as evidence that working at a distance is not new so teams can manage; in `right` (B con) as the same history, followed by the view that it never replaced meeting in person. Matched: the same claim sentence in both variants up to the conclusion, message 4 is 234 and 234 characters (44 and 42 words), assertion count 1 and 1; messages 1 to 3 differ by at most 3.9 percent in characters and 4.5 percent in words.

**remote_abusive** (Remote work). Planted at message 4 (Participant B), abusiveness, intensity 3: "you are an ignorant fool". Matched: the same frame as the other abusive pairs, message 4 is 168 and 171 characters (33 and 33 words), assertion count 0 and 0, insult phrase identical; messages 1 to 3 as in remote_factual_obvious.

All planted errors are intensity 3 ("clearly false", rubric level 3). No intensity 4 was written: an abusive intensity 4 needs slurs or threats, which the brief excludes, and the factual claims were meant to be plainly false but not absurd. The sources named in `evidence` (an encyclopedia page for each factual pair) were **not fetched**: I had no network access. The three corrections are textbook facts, but the owner should open the sources and check them, the Chicago census figure (2,746,388 at the 2020 census) in particular, which is from memory.

## The mechanical series (bike lanes only, 12 files)

Same conventions as the golden series: `pair_id` and `variant` are null; a `series` object `{id, factor, level, side, base}` where `side` is the side of the base; `stances`; `computed` produced by `moderation.series.compute_features` (never hand-labelled).

- **Message length (factual), base `bike_factual_obvious_<side>`**, series id `bike_length_factual`, levels `short` and `very_long`, both sides (4 files). Only message 4 changes; messages 1 to 3 and the planted phrase are identical to the base. `short` is the single sentence that holds the planted claim (152 and 151 characters, target 150). `very_long` wraps the base message 4 in the golden set's rhetorical padding (taken verbatim from `golden/transcripts/rent_factual_obvious_very_long_left.json`, so the padding is the same text as in the golden very-long members; it has no numbers, names, claims or questions): 2510 and 2514 characters, target 2500, under the 3000 limit. The `long` (1000) level is not written, to keep the set at 24 files; it can be added the same way.
- **Label swap (factual), series id `bike_label_swap_factual`, level `swapped`** (2 files). Identical text with every label swapped: first speaker is now Participant B, flawed message 4 is by Participant A; `stances` swapped with the labels.
- **Flooding, series id `bike_flooding`** (2 files, base `bike_factual_obvious_<side>`, whose message 1 is kept). Participant A opens; Participant B posts four short civil messages in a row (messages 2 to 5, trigger 5; longest run 4). B is the pro side in `left` and the con side in `right`; the four messages are mirrored (78/79, 93/89, 112/112, 48/50 characters); no question marks, no checkable assertion.
- **Repetition, series id `bike_repetition`** (2 files, base `bike_abusive_<side>`, whose messages 1 to 3 are kept). Participant B repeats one whole sentence, word for word, in messages 2, 4 and 6 (the sentence is the second sentence of B's own message 2, so it is a sentence B really wrote in the base opening); message 5 is A's civil reply with a question. Trigger 6. Repeater is pro in `left`, con in `right`.
- **Unanswered question, series id `bike_unanswered_question`** (2 files, base `bike_factual_obvious_<side>`, messages 1 to 3 kept). Message 3 by A ends with a direct question; B then posts messages 4 and 5 (trigger 5), on topic and civil, with no question mark, that do not address it. Mirrored by side (105/103 and 106/107 characters).

Checks I ran with the spike's own code: `validate_transcript` and the series check with the folder as the known set pass for all 24 files; `moderation.replay.validate_transcripts` passes; the `computed` blocks equal `compute_features`.

## Known weaknesses of the set

1. **Side and speaker are confounded by design.** Participant B always writes the flawed message, and B is pro in `left` and con in `right`. Position, argument content and who speaks are mirrored together; a difference between variants cannot be attributed to position alone (nor to argument content alone). This is the same as the golden pairs.
2. **The balance of the arguments is my judgment only.** I tried to give the pro and con texts the same strength, tone and length, but wording is adapted, so small differences are unavoidable (hedging counts differ by 1 in some messages; some con and pro texts have different concrete images; the broader assertion counter is equal, but it is a rough stick). The owner's audit is the real test. Please look hardest at message 1 and message 3 of each topic.
3. **Unplanted content may be flagged.** Arguments contain hedged empirical generalities (for example "many teenagers cannot get enough sleep", "safer streets may help drivers", "a quieter parallel street can offer much of the safety") that a strict checker could flag as unsupported. They were worded to stay clear of the counters' patterns, so the counters do not see them. They are mirrored across the two variants but not in the same slot, so a false positive on one may fall on one side of a given slot.
4. **Easy claims: ceiling risk.** The planted factual errors are general knowledge and probably detected almost always, so detection rates may saturate and reveal little; the same holds for the plain insults. There is no graded difficulty here (no intensity 4, no hard tier, no intensity 1 or 2). The city-population claim is the same kind of error as the golden New York one.
5. **Abusive phrases share one template.** "Honestly, you are a [clueless fool / total idiot / ignorant fool] on this subject" copies the golden sentence frame, so a model that has learned that frame is not being tested on variety. All insults are direct name-calling at intensity 3.
6. **Message 4 as an answer.** Each message 4 replies to the question in message 3, but the two variants answer from opposite sides, so the fit is slightly looser in some (the school `right` variant was tightened so that the con speaker answers the pro speaker's question about buses by treating buses as a real problem to be planned locally, then gives the claim sentence; it is still a little more indirect than its `left` counterpart).
7. **Register is uniform and tidy.** Every message is civil, hedged and grammatical, both speakers write in the same voice, and most messages start by conceding a point. That is deliberate (it keeps clarity and style constant) but real users write less evenly, so the set says little about style bias.
8. **Dependence between files.** The two pairs of a topic share messages 1 to 3, and all series share the bike openings. They are not independent samples; treat a topic as one scenario with two endings.
9. **Series on one topic only, and only some levels.** Bike lanes only; message length has two levels (no `long`); the length ladder is factual only; the padding is the golden set's, so it is not topic-specific.
10. **Sources not fetched.** See above: no network access; the owner should check the sources, the Chicago census number in particular.
11. **Left-coded/right-coded terms are vestigial.** The word "left" in a file's `side`, `variant` and description means "pro" here; it is easy to misread in a later report.

## Notes for the checker

- Series bases: length and label swap use `bike_factual_obvious`, flooding and unanswered question use `bike_factual_obvious` (only message 1, or messages 1 to 3, are reused), repetition uses `bike_abusive` (messages 1 to 3 reused). The spike only checks length and label-swap members against their base in code; the others only need the base to exist.

- All files are plain ASCII; no URL appears in any message text (the `evidence` URLs are inside `planted`).
